# PolyMeet

PolyMeet 是本機會議工作區，支援麥克風與分頁音訊錄音、即時逐字稿、雙語翻譯、音檔補轉及 AI 會議紀錄。

## 啟動

需要 Node.js 22.13+（22.x）、24.x 或 26+。後端使用 Node 內建的 SQLite。

```sh
npm install
npm run dev
```

開啟終端機顯示的網址。開發指令會同時啟動 Vite 與本機後端。正式版本可先執行 `npm run build`，再執行 `npm start`（或 `npm run preview`）並開啟 `http://127.0.0.1:3001`。執行 `npm run typecheck`、`npm test` 與 `npm run format:check` 可分別檢查型別、執行測試及檢查格式。開發伺服器固定使用 5173 埠；若該埠被占用，請先停止占用它的服務。

在介面設定中填入 API 金鑰與各功能的模型 ID；預設只在目前瀏覽器分頁保存金鑰；可在設定中選擇記住金鑰，跨分頁保留。也可複製 `.env.example` 為 `.env`，設定後端備用金鑰，重新啟動服務後生效。後端只監聽本機。可用模型依供應商帳號權限而異，呼叫服務可能產生費用。

首次部署時，可在 `.env` 設定 `POLYMEET_ADMIN_USERNAME` 和 `POLYMEET_ADMIN_PASSWORD`，伺服器會在空資料庫建立管理員。若要透過瀏覽器初始化，改設定 `POLYMEET_SETUP_TOKEN` 為至少 32 字元的隨機代碼，並於首次建立管理員時輸入該代碼。完成後可移除部署用憑證。Docker 部署時，請確認宿主機掛載的 `./data` 可由容器的 `node` 使用者寫入。

登入畫面與工作區的「設定」可切換介面語言，支援繁體中文、簡體中文、越南文與英文。瀏覽器會記住上次選擇。轉錄、翻譯與 AI 會議紀錄的語言可在各功能中設定。

曾使用登入功能上線前版本的使用者，可用原本的瀏覽器與網址登入目標帳號，從「資料備份」選擇「匯入舊版工作區」，確認畫面顯示的帳號後匯入。首次匯入會把舊版來源綁定至該帳號，並保留原始資料。相同帳號可重試，已存在的會議會略過。更新前已匯入的副本仍由原帳號保有。

用量日期與「今天／本週／本月」依伺服器的帳務時區（`TZ`）計算。新錄音按實際錄音區間分配跨日時長，排除暫停；舊錄音只有已錄總時長時，按各日所占的時間比例估算。模型用量與費用保留在請求開始日。個人歷史報表的「全部來源」會列出零費用的本機錄音。

缺少費率或供應商用量的請求會標為待核對。管理員可在「逐筆核對待計價用量」依起始時間和識別碼比對供應商紀錄，也可匯出逐筆待核對 CSV，填入實際美元金額（含確認的零費用）與核對依據，並更新已取得的 Token 數。系統會保留核對者、時間、依據及更正前後的金額。

## 從區域網路或 Tailnet 使用

在主機上執行 `npm run build`，把要使用的 HTTPS 網址加入 `.env`，再執行 `npm start`。網址用逗號隔開，並只填來源（協定、主機名稱及非預設埠）。

```dotenv
POLYMEET_HTTPS_ORIGINS=https://192.168.1.10:8443,https://my-node.my-tailnet.ts.net
```

- **Tailnet**：在主機上執行 `tailscale serve --bg http://127.0.0.1:3001`，將指令顯示的 HTTPS 網址填入上方清單。其他電腦連上 Tailnet 後即可開啟。若 Tailscale 提示啟用 HTTPS，請依提示完成設定。[Tailscale Serve 文件](https://tailscale.com/docs/reference/tailscale-cli/serve)
- **區域網路**：在主機上安裝 Caddy，將以下設定的 IP 換成主機的區網 IP。若 Tailscale Serve 的 HTTPS 功能無法啟用，也可加一個同樣的站台區塊，使用主機的 Tailnet IP。把各網址加入 `POLYMEET_HTTPS_ORIGINS`。用戶端電腦信任該主機的 Caddy 根憑證後，即可開啟相同的 HTTPS 網址。若主機開啟防火牆，請允許用戶端連到 TCP 8443。[Caddy 反向代理文件](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy) [Caddy 根憑證說明](https://caddyserver.com/docs/automatic-https#local-https)

```caddyfile
{
  auto_https disable_redirects
}

https://192.168.1.10:8443 {
  bind 192.168.1.10
  tls internal
  reverse_proxy 127.0.0.1:3001
}
```

將上方設定存成 `Caddyfile` 後，執行 `caddy run --config Caddyfile`。

麥克風和分頁音訊需要瀏覽器信任的 HTTPS。遠端使用者請在各自瀏覽器的設定填入 API 金鑰。會議資料依瀏覽器、裝置和網址分開儲存。[MDN 安全環境說明](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts)

## 錄音和會議資料

會議、逐字稿、會議紀錄及錄音片段保存在瀏覽器 IndexedDB。錄音約每秒寫入一個片段，暫停或離開頁面時會要求保存目前片段。需要重整時，請使用「儲存錄音並重整」：它會結束錄音，等已收到的資料寫入後再重整。直接重整或瀏覽器異常關閉時，只能取回已寫入的資料，不能保證保住尚未交付的最後一段。已保存的未定稿及未完成譯文會在逐字稿標示。請定期下載重要錄音。

即時轉錄連線未就緒或中斷時，會自動重試，並重播尚未完成的音訊。新的連線可帶入最多 500 ms 的前置靜音，避免重送已定稿的語音。若關閉即時轉錄，麥克風與分頁音量仍可在本機監測。錄音保存後，包含錄音中斷時保存的片段，都可在播放器選擇「轉錄此錄音」。若已有逐字稿，請選擇附加或覆蓋。只有轉錄成功且辨識出語音時，才會寫入新逐字稿。

選擇「麥克風 + 分頁音訊」時，分享視窗中須選擇提供音訊的來源並啟用音訊分享；實際選項取決於瀏覽器及作業系統。上傳大於 23 MiB 的音檔時，瀏覽器會先解碼並切為十分鐘 WAV 片段，因此需要足夠記憶體。上傳的原始音檔也會保存在本機；Google 音檔補轉使用 Files API，完成後會嘗試刪除雲端暫存檔，清理失敗時會提示。

若轉錄服務未回傳逐句時間，逐字稿會標示「片段起點」；播放時會從該上傳片段的開頭開始，而非精確的發話位置。

Gemini 音檔轉錄可辨識語者並提供近似的發言時間。OpenAI 可選 `gpt-4o-transcribe-diarize` 取得語者和分段時間，或選 `whisper-1` 只取得分段時間；僅回傳文字的模型只會標示切分起點。大型音檔分開辨識的語者標籤會註明分段編號，不會假設不同分段的同名標籤是同一人。按逐字稿上的「更名」可修改這一段，或批次修改同一錄音中的相同標籤；新的匯出和 AI 紀錄會使用更名後的標籤。

使用轉錄、翻譯或 AI 會議紀錄時，相關音訊或文字會傳送至所選的供應商。OpenAI 翻譯與會議紀錄請求會關閉 Responses API 的回應儲存。音檔補轉中斷時，保留目前選取的音檔並重新開始，可從尚未完成的片段繼續。

雙語會議會自動翻譯上傳音檔及已存錄音轉錄後的定稿段落。點選「補齊未譯段落」可批次翻譯缺少譯文或譯文未完成的逐字稿。修改原文後，舊譯文會清除，可點選「重新翻譯」處理該段。投影畫面的 `F` 切換全螢幕，`+`／`-` 調整字級。詳見 `PLAN.md`。

一般會議可設定逐字稿語言；雙語會議的語言設定也會用於音檔轉錄。選擇繁體或簡體中文時，系統會要求服務使用指定字形，並在適用時校正輸出。繁簡中文同時選用時，逐字稿依服務標註的字形校正，未標註時採用語言一。中文搭配日文時，系統校正可辨識的中文字形，保留無法判定語言的共用漢字。已保存的舊逐字稿和會議紀錄不會自動修改。雙語會議會在逐字稿段落定稿後開始翻譯，先顯示串流草稿，再校正完整譯文。AI 會議紀錄會按能保留 Markdown 結構的段落校正。
